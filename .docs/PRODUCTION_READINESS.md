# Production Readiness Assessment

Assessment date: **2026-10-14**, branch `feature/stage3-hardening` (stacked on PR #3 → PR #2 → PR #1). It applies the mission's §21 rule: a polished UI or a passing build alone does not make the system production-ready. Each dimension is judged on evidence in the repository, its tests, CI runs and the recorded QA. Gap classes are defined in [GAP_ANALYSIS.md](GAP_ANALYSIS.md).

**Ratings**

- **Ready**: implemented, tested, evidence linked.
- **Ready with conditions**: usable once the listed conditions are met.
- **Not ready**: a blocking gap.

## Verdict

| Deployment                                                                  | Verdict                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Single-till store, "this computer only" mode** (new or upgraded from 1.3) | **Ready for a supervised pilot** once go-live checks 1–8 pass on a test PC and the store printer ([GO_LIVE_TEST_PLAN.md](GO_LIVE_TEST_PLAN.md)) and the owner has decided K-24. Data, money and permissions are covered by tests; nothing has yet run on the store's own hardware. |
| **Multi-till store with a Docker server**                                   | **Ready with conditions:** go-live check 10 on the real network, the server PC on a UPS, `pg_dump` backups scheduled. Client tills use HTTPS with a pinned store root (G-24). A LAN or server outage stops the client tills: offline selling waits for owner policies (G-20).      |
| **Internet-facing server**                                                  | **Not supported:** the design targets a store LAN; there is no internet-facing hardening review.                                                                                                                                                                                   |

## Go-live

Follow [GO_LIVE_TEST_PLAN.md](GO_LIVE_TEST_PLAN.md): the automated rehearsal, then the test PC, the store printer and, if wanted, the second till. After the checks pass:

1. Decide K-24 (close formula) and K-10 (approval policy) ([OWNER_DECISIONS.md](OWNER_DECISIONS.md)).
2. Create the real accounts and roles, and change any PIN that was shared under the old system.
3. Set a backup routine: النسخ الاحتياطي → حفظ نسخة at least daily, to a USB drive or another PC. Keep `%APPDATA%\HeroMarket\heromarket.json` safe: it holds the server secret and the local database password.
4. Keep the old `%APPDATA%\elnagdi-pos` folder untouched for the rollback window ([DATABASE_MIGRATION.md §5](DATABASE_MIGRATION.md)).
5. First week: the owner reviews سجل العمليات and the shift reports daily.
