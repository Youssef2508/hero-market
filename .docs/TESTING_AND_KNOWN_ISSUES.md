### Test-harness defects (fixed in the redesign branch)

- **T-1** Suites never exit non-zero: the outer `catch` only logs. `run-all.js` + `process.exitCode = 1` fix this.
- **T-2** Several assertions are self-swallowed: `try { …; throw new Error('FAILED: …') } catch (e) { console.log('✔ PASSED …') }` – a failure is reported as a pass. Inner catches now rethrow `FAILED:` errors.
- **T-3** Suites require `%APPDATA%/elnagdi-pos/market_unified.db`; on CI or a fresh machine they cannot start. `db_helper.js` now bootstraps a fresh DB via `scripts/init-dev-db.js` when no source DB exists (or when `TEST_FRESH_DB=1`).

## 4. Redesign verification method

- **Static**: `npm run lint` (0 errors required), `npm run format:check`, `npm run build`.
- **SQL suites**: `npm test` (copy of the installed DB) and `npm run test:fresh` (fresh bootstrap) – both must pass; a deliberate failure was checked to exit 1.
- **Code review**: every changed file was compared with `HEAD` by independent reviewers (26 review units) and each finding was re-checked before fixing. Confirmed findings were fixed: dialog button order (5 dialogs), Esc on the new overlays, qty-button focus, stale search results, lost data fields (product count, best-day invoice count, exact daily totals), customer profile opened from the monthly report, sales "clear" button, crash screen in dark mode, icon script, Change PIN (K-18). Three units (inventory tab, CSS sweep, accessibility sweep) did not complete; the CSS sweep was replaced by scripted checks (no undefined `var(--…)`, no missing classes that affect layout).
- **Scripted UI QA** (Playwright over CDP against the running Electron window, disposable database via `HEROMARKET_DB_PATH`): screenshots of all 19 destinations in light and dark at 1366×768 and the cashier at 1000×630; interaction scripts for selling, shortcuts, dialogs, lock screen and the review fixes.
