**141 tests**, run by `npm test` (`tests/run-all.js`).

- Service suites need PostgreSQL: `HEROMARKET_TEST_DATABASE_URL`, or the `npm run pg:dev` cluster.
- If neither is available the run **fails**. Suites are never skipped silently.
- Each test file creates and drops its own database (`tests/service/helpers.js#freshDatabase`). Files run one after another (`--test-concurrency=1`).
- `npm run test:unit` runs the database-free suites only; `npm run test:service` runs the PostgreSQL suites only.

### Legacy simulation suites

The four SQLite simulation suites (`tests/simulate_*.js`) were removed with the SQLite engine. Their scenarios were ported to `flows.test.js`, `checkout.test.js` and `migration.test.js`.

Two scenarios were not ported, because they tested SQL the app never ran:

- stock increase on supplier purchase: the app records purchases financially only;
- points redemption: no redemption flow exists.

## 3. Continuous integration

`.github/workflows/ci.yml`, on every push and PR (details in [CI_CD.md](CI_CD.md)):

1. **Linux:** lint, format, build, `npm test` against a `postgres:17` service container, and an `npm audit` report.
2. **Windows:** `npm test` against the bundled PostgreSQL binaries (`scripts/pg-dev.js` through `pg_ctl`), unsigned `--dir` package, executable metadata, PostgreSQL binaries and package contents.
3. **Docker:** `docker compose -f docker-compose.test.yml run tests` (lint, build and all suites in containers), then the server stack (`docker compose up --wait`): health, `setupCodeRequired`, and the setup code in the log.
