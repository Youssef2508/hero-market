# Interfaces and Integrations

HeroMarket POS has two internal interfaces:

- **Electron IPC** between the renderer and the main process;
- the **HeroMarket service API**, reached in-process (local and standalone modes) or over HTTP on the store LAN (client mode).

There are no internet integrations, no telemetry and no payment-provider connections.

## 1. IPC channels (`src/preload/index.js` → `src/main`)

| Channel                                                 | Preload accessor                                                    | Request → response                                                                                                                                                                    |
| ------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `api:call`                                              | `window.api.call(op, body)` (used through `lib/api.js#api`)         | Operation name (`/^[a-zA-Z]+.[a-zA-Z]+$/`) + JSON body → `{ status, data }` or `{ status, error: { code, message } }`. The main process attaches the session token and terminal name. |
| `backend:status`                                        | `backend.status()`                                                  | → `{ configured, mode, ready, error, terminalName }` (waits for a start-up in progress)                                                                                               |
| `backend:configure`                                     | `backend.configure({ mode, databaseUrl, serverUrl, terminalName })` | Validates the URL shape, writes `heromarket.json` and restarts the backend → status                                                                                                   |
| `backup:save` / `backup:restore`                        | `db.backup()` / `db.restore()`                                      | Save or open dialogs around `backup.export` / `backup.restore`. Restore saves a safety export first.                                                                                  |
| `print-sale`                                            | `printer.printSale(data, { paper })`                                | Sale data → active template → line language → `print_receipt.ps1 -TemplateLayout`                                                                                                     |
| `print-template-test`                                   | `printer.testTemplate(config, sample)`                              | Designer test print                                                                                                                                                                   |
| `print-report`                                          | `printer.printReport(kind, data)`                                   | `kind` = `shift`                                                                                                                                                                      | `momkn` | `wallets` → `src/shared/reportLines.mjs` → printer |
| `sale-pdf`                                              | `printer.saleToPdf(data, config?)`                                  | A4 template → HTML → `printToPDF` → save dialog                                                                                                                                       |
| `print-receipt`                                         | `printer.print(html)`                                               | Legacy sale-receipt HTML (reprints) → `legacyReceiptText.mjs` → printer                                                                                                               |
| `generate-shortages-pdf` / `print-shortages-to-printer` | `generateShortagesPdf(items)` / `printShortagesToPrinter(items)`    | Typst PDF of shortages / plain-text list on the receipt printer                                                                                                                       |

## 2. HeroMarket service API (`src/server`)

- **Transport:** `POST /api/<operation>` with a JSON body (Fastify JSON schema per operation; 2 MB body limit, 512 MB for `backup.restore`).
- **Headers:** `authorization: Bearer <token>` and `x-heromarket-terminal: <name>` (set by the main process).
- **Errors:** `{ error: { code, message, details? } }` with status 400, 401, 403, 404, 409, 429 or 503.
- **Health:** `GET /api/health` → `{ status: 'ok' }` (used by the Docker health check and `cli.js health`).

## 3. Local binaries and scripts

| Asset                                                               | Used by                     | Notes                                                                                                         |
| ------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------- |

| `typst.exe`                                                         | Shortages PDF               | Windows binary, extra resource                                                                                |
| `resources/logo.png`, `brand-logo.png`                              | Receipt logo fallback       | The store's own logo (settings) takes precedence                                                              |
